Países e regiões

Sim, vale criar as tabelas

Hoje o país vem de uma lista fixa em lib/countries.ts (PT, ES, FR) e a região é texto livre. As landing pages de destino dependem de lib/regions.ts, que já precisa de listas de apelidos (match) para juntar grafias diferentes. Os dados de produção mostram o problema:

PaísValor em routes.regionRotas
PTNorte9
PTNorte Portugal4
PTNorth Portugal1
ESNorth Spain1
FRAlpes, Provença, Córsega…22

"North Portugal" não está no match da região Norte, então essa rota não aparece em /regions/norte. E a Normandia não tem página de destino. Com uma tabela, o autor escolhe de uma lista, os erros de grafia acabam e uma região nova vira página de destino sem deploy.

  • Leitura: pública.
  • Criar e editar: só curator e admin (RLS com a função de staff que já existe na migração 014).
  • Autor sem região na lista: escolhe a mais próxima e escreve uma sugestão; o curador cria a região na avaliação.
  • Detecção automática: guardar um bbox por região permite pré-selecionar país e região a partir do primeiro ponto do GPX.
Esboço do schema
create table countries ( code char(2) primary key, -- ISO 3166-1 flag text not null, name jsonb not null, -- {pt,en,es,fr,de} is_active boolean default true ); create table regions ( id uuid primary key default gen_random_uuid(), slug text unique not null, -- /regions/[slug] country char(2) references countries, name jsonb not null, intro jsonb, aliases text[] default '{}', -- substitui match[] bbox numeric[4], -- auto-detecção pelo GPX created_by uuid references profiles, created_at timestamptz default now() ); alter table routes add column region_id uuid references regions; -- backfill com os aliases de lib/regions.ts; -- routes.region (texto) fica até migrar tudo -- RLS: select para todos; -- insert/update/delete só is_staff()

CampoComo é preenchidoO autor pode
TítuloPadrão Nome | Partida > Parada > Chegada. O nome sai da estrada principal ou do nome do ficheiro; partida e chegada por geocodificação reversa do primeiro e do último ponto; o meio é a parada principal.Trocar o nome principal e escolher qual parada entra no meio.
Distância, desnívelDo GPX (já é feito hoje) ou do route builder.Corrigir num campo numérico com −/+, sem limite máximo.
Duração estimadaTempos do GPX quando existem; senão distância a ~40 km/h, arredondada a 5 min. O builder já calcula a sua.Editar horas e minutos separadamente.
Tipo de rotaPartida e chegada a menos de 1,5 km = circular; senão ida e volta. (Vale considerar um terceiro valor "só ida".)Trocar com um toque.
DificuldadePontuação a partir de desnível por km e curvas por km (variação de rumo).Trocar com um toque; o curador confirma.
CategoriaSugestão: montanha se altitude máx. > 1200 m ou > 25 m/km de subida; senão cênica. Costeira e aventura ficam como escolha do autor.Trocar com um toque.
País e regiãoPré-seleção pelo bbox da região que contém o primeiro ponto.Escolher de uma lista. Curador e admin também criam regiões.
ParadasWaypoints do GPX ou pontos do builder, ordenados pela posição no traçado.Renomear, mudar o tipo, remover, adicionar.
FotosFicam na fila no navegador e sobem para route_photos logo depois de criar a rota (o caminho precisa do id).Autor, curador e admin gerem. A RLS da migração 014 já permite isso.
